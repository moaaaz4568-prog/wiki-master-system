# نظام ويكي الماسترز

نظام ويكي عام يحوّل ملفاتك إلى «عقل»: تقرأ مصادرك، تستخرج منها المفاهيم، تعمّقها، تجمعها، وتبني منها كتب قرار (ماسترز) — وبعدها تسأل النظام فيجيبك باستشهاد حرفي من مصادرك، بصوت الشخصية التي اخترتها.

> **الحالة: PROPOSED** — هذه معمارية مقترحة موثّقة، ليست نظاماً يعمل بعد. التشغيل الفعلي NOT_RUN.

## دورة الحياة — ببساطة

```
ملف المصدر ← مفهوم ← تعميق المفهوم ← تجميع المفاهيم ← ماستر
```

1. **اقرأ ملف المصدر كاملاً** سطراً بسطراً.
2. **استخرج كل فكرة مميزة** — ملف لكل فكرة (`C_<CODE>_NN.md`)؛ مصدر بلا فكرة = لا ملف.
3. **عمّق المفهوم** (تعريف، تحليل، محاكاة، توقّع، طريقة عمل، أمثلة، أخطاء قاتلة).
4. **اجمع المفاهيم** وحوّلها إلى **ماستر**: كتاب قرار مرتبط بنطاق وحاجة وتغطية.

## ماذا عن الذرات والـ Claims؟

- **الذرات (T_): لا وجود لها هنا.** كانت طبقة وسيطة في النظام القديم (تقطيع المصدر إلى جُمل صغيرة)، وبُنيت ثم رُميت. النظام الجديد يقرأ المصدر مباشرة ويحوّله إلى مفهوم — بلا طبقة ذرات.
- **الـ Claims: موجودة، لكنها ليست ملفات كثيرة.** الـ Claim جملة واحدة قابلة للفحص (مثلاً: «المنتج X زاد مبيعاته 40% في 2023») مربوطة بمصدرها وموضعها واقتباسها الحرفي. غالباً يعيش الـ Claim **داخل** ملف المفهوم كسجل دليل، ولا يُفصل في ملف مستقل (`CLM_<id>.md`) إلا إذا أُعيد استخدامه، أو كان خلافاً، أو استنتاجاً مركّباً يحتاج مراجعة مستقلة.
- **سلسلة الاستشهاد:** الإجابة ← مفهوم/ماستر ← Claim ← المصدر الخام + الموضع + الاقتباس.
- **الخلاف لا يُحذف ولا يُخفى:** إذا قال مصدران شيئين متعارضين، يُعرض الطرفان معاً.
